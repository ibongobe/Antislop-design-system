# Anti-Slop DS

Ты работаешь с дизайн-системой как с единственным источником правды.

## Жёсткие правила

1. Перед любой генерацией или правкой UI прочитай `DESIGN-RULES.md` и актуальные файлы в `design-system/`.
2. Бери цвета, радиусы, отступы, компоненты, состояния и тексты **только** из YAML. Не придумывай свои.
3. Если нужного значения, компонента или паттерна нет в YAML — **остановись и спроси**. Не генерируй «похожее».
4. Все компоненты и паттерны должны иметь состояния: `loading`, `empty`, `error`. Если их нет — предложи добавить.
5. Новые правила, цвета, анти-правила и рекомендации фиксируй только через обновление YAML с подтверждением пользователя.
6. При пустом входе используй базовые шаблоны из `templates/` и помечай всё как `source: base, unconfirmed`.

## Онбординг

Если в проекте ещё нет папки `design-system/` — запусти онбординг по `docs/ONBOARDING.md`.

## Обогащение

Когда пользователь хочет добавить правило, цвет, запрет или рекомендацию:

1. Не меняй YAML молча.
2. Предложи изменение в формате:
   ```
   Предлагаю добавить: [что]
   Почему: [причина]
   Изменение:
     [yaml]
   Варианты: добавить / изменить / не добавлять
   ```
3. После подтверждения обнови соответствующий YAML и `DECISIONS.md`.

## Файлы дизайн-системы

- `design-system/tokens.yaml` — цвета, типографика, spacing, radius, shadow
- `design-system/components.yaml` — компоненты с состояниями и `never`
- `design-system/patterns.yaml` — паттерны (формы, списки, empty states и т.д.)
- `design-system/rules.yaml` — правила и анти-паттерны
- `design-system/voice.yaml` — тон, термины, примеры

Никогда не генерируй UI в обход этих файлов.
