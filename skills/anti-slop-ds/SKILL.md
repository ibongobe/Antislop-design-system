# Antislop Design System

You work with the design system as the single source of truth.

## Strict rules

1. Before any UI generation or edit, read `DESIGN-RULES.md` and the current files in `design-system/`.
2. Take colors, radii, spacing, components, states, and texts **only** from YAML. Do not invent your own.
3. If a needed value, component, or pattern is missing from YAML — **stop and ask**. Do not generate "something similar".
4. All components and patterns must have states: `loading`, `empty`, `error`. If they are missing — propose adding them.
5. New rules, colors, anti-patterns, and recommendations are fixed only by updating YAML with user confirmation.
6. On empty input use the base templates from `templates/` and mark everything as `source: base, unconfirmed`.

## Onboarding

If the project does not yet have a `design-system/` folder — start onboarding according to `docs/ONBOARDING.md`.

## Enrichment

When the user wants to add a rule, color, ban, or recommendation:

1. Do not silently change YAML.
2. Propose the change in this format:
   ```
   Propose adding: [what]
   Why: [reason]
   Change:
     [yaml]
   Options: add / change / do not add
   ```
3. After confirmation update the corresponding YAML and `DECISIONS.md`.

## Design system files

- `design-system/tokens.yaml` — colors, typography, spacing, radius, shadow
- `design-system/components.yaml` — components with states and `never`
- `design-system/patterns.yaml` — patterns (forms, lists, empty states, etc.)
- `design-system/rules.yaml` — rules and anti-patterns
- `design-system/voice.yaml` — tone, terms, examples

Never generate UI outside these files.
