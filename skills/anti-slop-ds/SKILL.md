# Antislop Design System

You work with the design system as the single source of truth. When applied to an existing project (especially cabinets/dashboards), the goal is a clear "wow" effect: modern, consistent, beautiful UI that feels intentionally designed.

**Density system**: User chooses interface density during onboarding (compact / normal / airy). Use the corresponding variant from `templates/systems/` for radius, spacing, typography, cards, layouts, etc.

**Color matching**: Prefer ready palettes from Mobbin brand colors (see `templates/systems/colors.yaml`). If user provides hex or brand, find the closest preset and build a consistent full palette (neutrals + accent + status).

**Visual etalon**: HeroUI for component structure, animations, and interactivity. Tabler Icons by default.

## Strict rules

1. Before any UI generation or edit, read `DESIGN-RULES.md` and the current files in `design-system/`.
2. Take colors, radii, spacing, components, states, texts, and icons **only** from YAML. Do not invent your own.
3. If a needed value is missing from YAML — **stop and ask**.
4. All components and patterns must have states: loading, empty, error.
5. **Density first**: After user chooses compact/normal/airy, assemble the design system by copying the matching variants from `templates/systems/` into the project `design-system/`.
6. **References are primary**: Deeply analyze user references and override density defaults where the reference clearly differs.
7. **Fonts are strict**: Use exact user-specified font.
8. **Icons**: Tabler outline by default. Always respect icon_text_gap from the chosen density.
9. **Color consistency**: Use Mobbin-inspired presets or closest match. Generate full semantic set.
10. **Cabinet standards**: Max 2 buttons in modals, consistent grids, proper cards.

## Onboarding

Follow `docs/ONBOARDING.md`. Critical question: density (compact / normal / airy). Then assemble systems accordingly.

## Design system files (assembled per density)

- tokens.yaml (merged from systems)
- radius.yaml / spacing.yaml / typography.yaml / colors.yaml (or merged)
- components.yaml
- patterns.yaml
- rules.yaml
- voice.yaml

Never generate UI outside these files.
