# Antislop Design System

You work with the design system as the single source of truth. When applied to an existing project (especially cabinets/dashboards), the goal is a clear "wow" effect: modern, consistent, beautiful UI that feels intentionally designed.

**Primary visual etalon: HeroUI**
- Soft surfaces and hierarchy instead of hard borders.
- Larger, softer radii (never tiny sharp corners).
- Subtle elevation (shadows) over outlines.
- Neutral palette from HeroUI default theme (oklch neutrals).
- Semantic variants, compound components, smooth interactions.

**Density system**: User chooses compact / normal / airy. Use matching variants from `templates/systems/`.

**Color**: Default to HeroUI neutrals. If user gives brand color — adapt the HeroUI surface system around the closest matching accent.

**Icons**: Tabler outline by default. Respect density icon_text_gap.

## Strict rules

1. Before any UI generation or edit, read `DESIGN-RULES.md` and the current files in `design-system/`.
2. Take colors, radii, spacing, components, states, texts, and icons **only** from YAML. Do not invent your own.
3. If a needed value is missing from YAML — **stop and ask**.
4. All components and patterns must have states: loading, empty, error.
5. **Density first**: Assemble from `templates/systems/` based on chosen density.
6. **HeroUI style priority**: Prefer soft surfaces, subtle borders/separators, larger radii, and elevation over hard outlines. Never default to tiny radii or heavy borders.
7. **References are primary**: Deeply analyze user references and override where they clearly differ, but keep HeroUI-level polish.
8. **Fonts are strict**: Use exact user-specified font.
9. **Cabinet standards**: Max 2 buttons in modals, consistent grids, proper soft cards.

## Onboarding

Follow `docs/ONBOARDING.md`. Critical: density choice. Then assemble HeroUI-inspired systems.

## Design system files (assembled per density)

- tokens.yaml (merged from systems)
- systems/ (radius, spacing, typography, colors, cards, layouts)
- components.yaml
- patterns.yaml
- rules.yaml
- voice.yaml

Never generate UI outside these files. Aim for clean HeroUI-like quality.
